**What it says**
- Row-static is the right decomposition for a row-major stencil: best at every thread count.
- Scaling saturates near **5×** on 12 physical cores. Two 8.4 MB grids per step is a memory-bandwidth-bound loop; more cores past ~8 mostly wait on the same DRAM.
- `schedule(dynamic)` with the default chunk of 1 row costs a third of the throughput — runtime scheduling overhead on ~1 ms of work per row.
- 24 threads is worse than 12 on every variant: two SMT threads per core share one load/store path on a loop that is already bandwidth-bound.

**Not measured:** the Henry2 Gold6130 numbers the assignment asked for. Those need the cluster.

### Part 1 — MESI vs MSI, 7-pattern Miranda bus suite, 4 cores (sums over the 4 L1s)

| pattern | GetX MSI → MESI | what happened |
|---|---|---|
| disjoint_read_then_write | **32 → 0** | S→E 32, E→M 32: private lines are read into E and written silently |
| disjoint_read_only | 0 → 0 | (MESI: I→E 32, no bus cost either way) |
| disjoint_writes | 32 → 32 | writes miss straight to M under both |
| mixed_rw_upgrade | 500 → 500 | shared lines never enter E; 1,234 invalidations under both |
| shared_write_pingpong | 1000 → 1000 | 992 invalidations, 992 interventions under both |
| shared_read_only, single_line_read_sharing | 0 → 0 | pure read sharing |

The E state pays exactly where the textbook says: private data read then written.
On shared-line patterns MESI is bit-identical to MSI. Simulated time moves by
~1 ns in 4 µs — in this bus model the upgrade is cheap, so the win is in
traffic, not latency. (`results/miranda/*.out:75`)

### Part 2 — migratory sharing: read miss promoted to GetX (`src/MESI_L1.cc:270-279`)

4 cores, one read→write pair each on one line (`traces/prospero_core{0..3}.trace`):

**Do not cite "S→M upgrades 0."** That counter reads 0 in the base run too — the
upgrade passes through a transient SM state that `Counters.h::recordTransition`
does not canonicalise. The evidence for the base upgrades is GetX 4 and S→I 3.
